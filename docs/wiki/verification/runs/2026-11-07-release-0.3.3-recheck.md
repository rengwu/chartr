# Release 0.3.3 fixture recheck

This follow-up preserves the initial [Failed candidate run](2026-11-07-release-0.3.3.md).
It verifies a test-fixture correction, not a change to shipping application or
backend behavior. Native desktop/banner checks and the user-skipped upgrade
scenario remain unverified; the aggregate is **Untested**.

## Build and correction

Fixture commit `56ce59cfe7a3f1d2286ebf04c8a6ca652839d1f2` changes only
`crates/chartr/tests/support/mouse.rs` compared with package candidate
`1b16fee02cac5ab5e7f135707d473f1f0730666e`. The
[comparison and binary hashes](../../evidence/2026-11-07-release-0.3.3/fixture-recheck-identity.json)
establish unchanged shipping source and byte-identical local normal app/sidecar
binaries before and after the correction. The original candidate's package
inspection remains applicable to those unchanged shipping inputs.

The killed-TUI test previously required one contiguous success marker in the
attach stream. That stream describes screen updates, so it can omit unchanged
cells and split text across repaint sequences. The CI failure occurred at this
final assertion after the mouse-mode checks. The corrected test waits for a
distinct file written by the shell in each scenario and reads the backend's
visible text to reject leaked mouse coordinates. Mouse enable/disable,
detached-session and handoff assertions are retained.

A local long-prompt attempt against the original fixture passed; it did not
reproduce the intermittent failure. The initial CI receipt and raw failure log
remain linked from the failed run.

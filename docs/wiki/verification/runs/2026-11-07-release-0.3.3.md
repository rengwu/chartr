# Release 0.3.3 candidate preparation

All executed local checks pass, but candidate macOS CI failed its killed-TUI
fixture's final screen-text assertion. The aggregate is **Failed**, preserving
that executed failure. Native interaction and OS notification delivery remain
unverified; automated fixtures do not establish those paths. The user requested simple checks without desktop
takeover and explicitly skipped the v0.3.2 upgrade scenario. See
[release scope](../../development/release-0.3.3.md).

## Build and scope

Base HEAD `369298062bfd5ba00ad0c273d580ce408797b19c`, branch `release/0.3.3`,
version 0.3.3 with local naming, frame-inset and mouse-recovery changes. macOS
Apple silicon, pinned Rust 1.96.0. The [identity](../../evidence/2026-11-07-release-0.3.3/identity.json)
records the tracked diff fingerprint, all source/build-file hashes including
the new naming module, toolchain and OS. The
[post-check identity](../../evidence/2026-11-07-release-0.3.3/checked-identity.json)
records built executables and confirms the source hashes remained unchanged.

Selected areas: `FEAT-terminals`, `FEAT-session-lifecycle`, `FEAT-settings`,
`FEAT-panes` and `FEAT-distribution`. Existing GPUI tests use the headless test
platform. Real-session tests create disposable `/tmp/cr-*` namespaces and shells;
their fixtures stop only their own daemons. No personal app/profile, backend,
desktop window, keyboard/mouse or provider account was controlled.

## Limits and follow-up

banner/click, live-provider naming flow or physical input was exercised. Source
review confirms the rename dialog's validation/cancel/identity guards but is not
an executed pass. Historical frame evidence does not cover all themes, sizes or
plugin surfaces. The mouse fixture explicitly restores shell termios; the patch
does not restore extended keyboard modes or diagnose memory pressure.

remain documented. Current feature descriptions were corrected for Geist,
released Close All Sessions, and the expanded Herdr patch while preserving dated
history. No new product code was changed during preparation beyond version

## CI fixture diagnosis

The failed attach buffer contains the final command and cursor-positioned pieces
of its output, rather than the contiguous `CHARTR_INPUT_OK` string the test
requires. This is a screen-diff stream: matching cells can be omitted and repaint
sequences can split text. The mouse-mode assertions had already completed before
this final readiness check. A [long-prompt local retry](../../evidence/2026-11-07-release-0.3.3/long-prompt-baseline.log)
passed and did not reproduce the intermittent failure; its
[command/result](../../evidence/2026-11-07-release-0.3.3/long-prompt-baseline.json)
is retained.

The follow-up changes only the test fixture: observe a distinct file written by
the shell for each scenario and inspect `pane.read` visible text for leaked mouse
coordinates. All actual attach mouse-mode assertions are retained. The original
CI failure above remains Failed; the [separate recheck](2026-11-07-release-0.3.3-recheck.md)
records execution of the correction.
